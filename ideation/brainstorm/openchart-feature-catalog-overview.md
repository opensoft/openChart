- **Catalog-to-staging pipeline** — bulk-promote selected feature entries into staged topics under `ideation/staging/` when proposal scoping begins.
- **Parity matrix generator** — machine-diff this catalog against an OpenEMR feature census to publish a live beat-OpenEMR scorecard.

- **Coverage heat reporting** — dashboard counting features per domain versus implementation milestones as build progresses.

## Focus

Give product, engineering, and governance one navigable place where every planned openChart capability is individually named, bounded, and traceable — at roadmap-line granularity, not domain-essay granularity.

## Motivation

The companion strategy packet (`openchart-feature-list`) established twelve feature domains and the differentiation thesis through competitive research. Strategy-level documents cannot answer "what exactly do we build first?" — that requires enumerating capabilities one decision at a time. This catalog decomposes those domains into 1,000+ atomic feature documents, each carrying a concrete behavior specification and its Frappe-native realization path, so downstream staging and OpenSpec work starts from clear units instead of re-deriving them from prose.

## Goals

Observable outcomes: any stakeholder can find whether a capability exists in the plan within seconds via the ID or search; every entry states actor, inputs, outputs, states, and edge cases well enough to seed acceptance criteria; every entry names its OC DocTypes, workflow states, roles, hooks, API surface, and print/report/dashboard surfaces so Frappe feasibility is never discovered late; domain syntheses group members into coherent subgroups so review happens cluster-by-cluster.

## Non-goals

Not specifications — every entry stays `Status: brainstorm` until promoted through staging. Not implementation tickets — no task breakdowns or estimates live here. Not vendor documentation — enterprise capabilities informed these entries but nothing is copied verbatim. No duplication of the strategy packet's competitive analysis; this index references it and moves on.

## What the system delivers

Twenty-two domain clusters follow. Each opens with its synthesis document (members, joints, emergent behavior, tensions), then a table indexing every feature: stable `<DOM>-<NNN>` identifier, linked title, and one-line summary. Features average roadmap-line granularity — things a product owner accepts or rejects individually — while remaining small enough to promote independently into staged topics and, later, OpenSpec requirements.

Access feeds care; care generates business events; exchange carries money and data outward; the intelligence-and-platform ring instruments and underlies everything. (*rcm/fin financial-domain entries live inside the wave-3 expansion of this catalog where quotas assigned them.)

## Key decisions and open questions

- Identifier stability governs everything: `<DOM>-<NNN>` values become citation keys downstream, so renumbering is forbidden once this overview publishes; gaps from culled entries stay gaps.
- Quota discipline (per-wave minimums) traded some unevenness between domains; ENG and DOC run deepest, TEL and IAX shallowest — deliberate, matching differentiation weight.
- Which entries graduate to staged topics first: highest beat-OpenEMR-leverage features (e-prescribing stack, closed-loop results, ambient capture, two-way messaging) are the natural first staging cohort.
- A cull pass is expected before any staging move: overlap between near-neighbor entries (for example reminder variants across msg and sch) gets resolved by merging into the stronger document, never by silent deletion.
